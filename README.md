# Создание резервных копий

Небольшая программа на Node.js и TypeScript для резервного копирования файлов из исходного каталога.

## Требования

- Node.js
- `tar` (обычно уже установлен в macOS и Linux)

## Установка

```sh
npm install
```

## Запуск

```sh
npx ts-node ./src/index.ts ./source ./backups
```

Программа проверяет только обычные файлы непосредственно в `source`. Если набор имён изменился, она создаёт архив `backup-<дата-время>.tar.gz` в `backups`. Вложенные каталоги не участвуют в проверке изменений.

Результат каждого запуска записывается в `backups/backup_log.txt`. После успешного создания архива в этом же файле сохраняется хеш набора имён файлов для следующего запуска.

## Демонстрация

Создайте тестовый исходный каталог и файл:

```sh
mkdir -p source backups
echo "Первый файл" > source/example.txt
```

Запустите программу. Должен появиться архив и запись `SUCCESS`:

```sh
npx ts-node ./src/index.ts ./source ./backups
```

Запустите программу ещё раз без изменений. Новый архив не появится, а в журнале появится `SKIPPED`:

```sh
npx ts-node ./src/index.ts ./source ./backups
```

Добавьте или удалите файл в `source` и запустите программу снова — будет создан новый архив.

## HTTP-сервер

Сервер использует встроенный модуль `node:http` и по умолчанию слушает порт `3000`. Запуск:

```sh
npm run server
```

Порт можно изменить через переменную окружения `PORT`.

### Описание задания

Сервер реализует два маршрута:

- `GET /search?q=node` возвращает переданное непустое значение `q`. Если параметр отсутствует, пустой или содержит только пробелы, сервер отвечает `400` и JSON с описанием ошибки.
- `POST /users` принимает JSON-объект с полями `name` и `age`, проверяет, что имя непустое, а возраст — целое неотрицательное число, и возвращает созданные поля со статусом `201`. Дополнительные поля игнорируются.

Для `POST /users` также проверяются тип содержимого и корректность JSON. Максимальный размер тела — 1 MiB: превышение из `Content-Length` отклоняется до чтения тела, а для потоковой передачи размер контролируется во время чтения.

Покрытие разделено на два файла: `tests/http-server.test.ts` проверяет валидацию данных, а `tests/http-server.integration.test.ts` отправляет HTTP-запросы к запущенному серверу и проверяет статусы, заголовки и ответы.

### Статусы ответов

| Метод и путь | Условие | Статус | Ответ или заголовок |
| --- | --- | --- | --- |
| `GET /search?q=...` | `q` передан и содержит символы, отличные от пробелов | `200` | `{ "q": "<значение>" }` |
| `GET /search` | `q` отсутствует, пустой или состоит из пробелов | `400` | JSON с полем `error` |
| `GET` на другой путь | Путь не поддерживается | `404` | `{ "error": "Not Found" }` |
| Метод не `GET` для `/search` | Метод не поддерживается | `405` | `{ "error": "Method Not Allowed" }`, `Allow: GET` |
| `POST /users` | Валидный JSON-объект с непустым `name` и целым неотрицательным `age` | `201` | `{ "name": "<имя>", "age": 25 }` |
| `POST /users` | Некорректный JSON или значения полей | `400` | JSON с полем `error` |
| `POST /users` | Тип содержимого не `application/json` | `415` | JSON с полем `error` |
| `POST /users` | Тело больше 1 MiB | `413` | `{ "error": "Payload Too Large" }` |
| Метод не `POST` для `/users` | Метод не поддерживается | `405` | `{ "error": "Method Not Allowed" }`, `Allow: POST` |

Лишние поля в запросе `POST /users` игнорируются и не попадают в ответ. Корневое значение JSON должно быть объектом.

Пример создания пользователя:

```sh
curl -i -X POST http://localhost:3000/users \
	-H 'Content-Type: application/json' \
	-d '{"name":"Anna","age":25}'
```

## Streams

Задание Streams добавлено отдельно от предыдущих: `WithTime` находится в `src/streams/with-time.ts`, а потоковый экспорт реализован в `src/streams/export-csv-to-txt.ts` с помощью `csvtojson` и `pipeline()`.

Запустить демонстрацию `WithTime` с запросом к JSONPlaceholder:

```sh
npm run streams:with-time
```

Экспортировать фильмы с фильтрами по умолчанию (`minYear: 1995`, `minRating: 8.5`):

```sh
npm run streams:export
```

Исходный файл: `src/assets/movies.csv`. Результаты создаются рядом с ним: `movies.txt` содержит по одному JSON-объекту на строку, `summary.json` — статистику обработки. Вызов `exportCsvToTxt({ minYear, minRating })` позволяет задать другие пороги. CSV обрабатывается построчно, результаты не накапливаются в массиве, а `pipeline()` управляет backpressure и закрытием потоков при ошибках.
